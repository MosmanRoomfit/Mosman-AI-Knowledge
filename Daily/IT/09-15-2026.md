## Main Workstreams

### 1. Odoo Stage 2 End-to-End Test

Priority is now to run the full workflow in the testing database rather than continue adding isolated automations.

Goal:
- Validate CRM → Won → Project
- Validate Project coordination model
- Validate Purchase / Production / Planning handoffs
- Validate Installation scheduling and completion
- Identify missing Activities, approvals, exceptions, dependencies and handoffs

### 2. Project / Task / Activity Structure

Project should act mainly as the coordination layer for:
- Assignee
- Deadline
- Waiting
- Approval
- Exception
- Handoff

Tasks should represent real work packages with an owner, output and duration.

Small follow-ups, phone calls, approval reminders and similar actions should be managed as Activities rather than being converted into Tasks.

### 3. Odoo Email Alias + Microsoft 365 Architecture

Still needs to be finalized for functional mailboxes such as:
- sales@
- design@
- production@
- project@
- account@

Key requirement is to preserve correct Odoo thread matching while allowing customers and suppliers to use normal department addresses without accidentally sending directly to technical Odoo catchall/reply-routing addresses.

### 4. Planning / Installer Workflow

Target workflow:

Planning
→ Ready to Schedule
→ Scheduled
→ In Progress
→ Done

Planning / Installer work includes:
- Assign installer
- Installation Date
- Planning Shift / Gantt scheduling
- External contractor communication
- Schedule change notifications

### 5. Installation-Date-Driven Deadlines

Installation Date should drive downstream/upstream production deadlines such as:
- Installation
- BOM
- CNC
- Manufacture / Production

Existing automation tests need to be consolidated and verified as one consistent production deadline workflow.

### 6. CRM Follow-up Automation

Continue validating:
- Last Outgoing Email
- Last Customer Reply
- No Reply detection
- Activity / reminder creation
- Pipeline monitoring

### 7. Outlook → Odoo Email Sync

Target behaviour:
- Read only Inbox messages
- Process read and unread mail
- Skip messages explicitly categorized as Odoo
- Match correspondence to the correct CRM opportunity/project using customer, address and project context
- Avoid duplicates
- Back up only high-confidence unmatched correspondence into Odoo

Current result:

- Current imported documents are still relatively lightweight and need more operational detail

Next knowledge-base task:

- Treat GitHub as the primary knowledge source during this test period
