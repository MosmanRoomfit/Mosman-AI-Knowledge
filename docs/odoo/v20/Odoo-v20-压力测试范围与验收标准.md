核心链路：**用户 Prompt → MCP 理解与调用 → Odoo 执行 → MCP 回读 → 结果交付**。

## 1. 测试目标与范围

本轮所称“压力测试”偏向功能链路验证：用明确、复杂、连续和异常的业务 Prompt，检查指定 MCP 能否在 Odoo 中完成真实操作，并准确报告结果。重点是意图理解、工具选择、业务执行、关联正确、结果回读及全过程耗时。

连续执行多个功能用于检查链路稳定性，不设置批量数据规模、并发档位、容量池或持续负载指标；本轮结果不能用于宣称服务器承载能力。

### 1.1 纳入范围的 17 个 App

Discuss、Calendar、Appointments、To-do、Knowledge、Contacts、CRM、Sales、Dashboards、Accounting、Documents、Project、Timesheets、Planning、Sign、Employees、Approvals。

“全功能”以实际启用的菜单、子功能和配置为边界。执行前逐项盘点并编号；App 图标只能证明入口可见，不能证明全部功能可用或 MCP 均能操作。

### 1.2 排除与暂缓项

- 排除 Link Tracker、Apps、Settings、Website、Surveys。
- 不安装、升级或卸载模块。账号、权限、公司、时区及连接配置只作前置只读核查。
- Sales 报价单创建、修改、发送及原生报价 PDF 导出暂缓；已有报价不改动。
- 库存、采购、制造不纳入本轮；已有盘点数据不自动应用。
- 只使用用户指定的 Odoo v20 — qiaoyutesting MCP；不使用 Odoo Ultimate 2，不连接或修改生产库。
- 消息、会议邀请、排程发布、签署邀请等必须使用已确认的测试对象及通知隔离方式，不发送给真实业务对象，不执行真实支付或真实合同签署。
- 本方案不自动执行 Odoo 写入，也不自动提交 GitHub。

### 1.3 v19 对比边界

没有 v19 独立测试库，当前仅做官方资料对比。不能给出 v19 实测速度、稳定性或 MCP 跑通结论，也不能将资料中描述的变化直接认定为本库已启用。

## 5. Prompt → MCP → Odoo 的链路验收

### 5.1 每条用例的执行过程

1. 理解 Prompt：明确对象、动作、条件、期望结果及边界。
2. 核对前置条件：确认指定 MCP 连通、目标测试库、公司、账号及实际版本证据；目标记录必须唯一。
3. 选择工具：核对模型、字段、参数及原生业务方法；没有对应能力时记录缺口。
4. 执行 Odoo 动作：按业务顺序操作，记录每步响应与真实 ID。
5. MCP 回读：检查最终字段、关系、状态、金额及必要日志；遇到超时先查询动作是否已完成。
6. 交付结果：输出实际完成内容、未完成项、证据和真实耗时；涉及导出时核验实际文件。

### 5.2 核心通过条件

| 检查点 | 通过条件 |
|---|---|
| 意图理解 | 正确识别创建、修改、查询或取消，不漏要求，不扩大范围。 |
| MCP 连接与目标 | 调用的是指定 qiaoyutesting MCP，目标库及公司有证据；工具名称本身不能证明实际版本。 |
| 工具与参数 | 模型、记录 ID、字段、时区、币种及业务方法正确。 |
| 真实执行 | Odoo 中有真实操作结果；不能只返回计划或凭成功提示断言完成。 |
| 关联及计算 | 客户、项目、任务、员工、文件等实际关系正确；工时、税额和金额独立核算一致。 |
| 业务状态 | 原生动作及规则得到验证；直接改状态字段不能代替过账、审批、发布或签署。 |
| 异常处理 | 无权限、条件不足或错误输入得到明确反馈，无意外写入；这是异常用例通过，不是业务操作成功。 |
| 重试处理 | 先检查已有结果，按请求语义决定恢复、重试或新建；不产生非预期重复。 |
| 多步骤结果 | 每一步有实际证据；部分完成如实列出，不报告整条链路成功。 |
| 文件交付 | 原生导出文件真实生成、下载且可打开；本地拼装文件不能冒充 Odoo 原生输出。 |
| 计时与报告 | 原始时间可追溯，人工等待、工具调用、下载和核验分别记录，不编造耗时。 |

当前不设置统一响应秒数。先记录每类功能的真实耗时；如业务另有时限，应在执行前固定并按该标准验收。

### 5.3 MCP 能力不足时

- 缺少模型访问、原生动作或文件导出工具时，相关 MCP 链路标记 Blocked，并写明缺少能力。
- 不使用其他 Odoo 连接器绕过指定 MCP，也不把字段修改包装为原生业务完成。
- 浏览器补充操作须有对应步骤的明确授权，分别记录 MCP 与浏览器结果。此前报价打印授权不自动扩展到其他功能。
- 超时或返回不明确时，先查询结果；无法确认是否写入时停止该步骤并标记不确定，避免盲目重复操作。

## 6. 异常与连续功能稳定性

| 场景 | 要检查的行为 | 通过条件 |
|---|---|---|
| 缺少必填信息 | Prompt 缺少必要对象、日期或金额 | 明确补充项；不猜测后执行关键写入。 |
| 重名或歧义 | 多个客户、任务或员工同名 | 列出候选或要求唯一 ID，不随意选第一条。 |
| 错误输入 | 不合法日期、不存在 ID、无效关系 | 返回明确错误，检查没有意外记录。 |
| 规则／配置不足 | 未设置审批人、税率或同步机制 | 标记阻塞，不捏造规则或联动。 |
| 权限不足 | 非授权角色执行审批或读取受限信息 | 拒绝符合实际权限，数据未越权修改或暴露。 |
| 连接或工具失败 | MCP 断连、响应错误、超时 | 区分连接失败和业务失败，核查既有写入再恢复。 |
| 重复 Prompt | 同一请求重试，或明确要求再建一条 | 区分重试和新请求；重复行为符合约定，记录证据。 |
| 中途失败 | 多步骤前面成功、后面失败 | 完成项和失败项明确，恢复不产生非预期重复或断裂关系。 |
| 连续不同功能 | 连续执行若干 App 操作 | 不串用上一条 Prompt 的客户、ID、公司或角色；每条独立回读。 |
| 结果表述错误 | 工具提示成功但对象、文件或状态不符 | 回读发现差异并判失败，不生成虚假成功报告。 |

连续测试用于观察链路上下文、错误处理与结果一致性，不产生并发容量或服务器性能结论。
